# P1-01 — SearchType HYBRID_COMPLETION plumbing

**Status:** completed

## Goal

Add `SearchType::HybridCompletion` (wire `"HYBRID_COMPLETION"`) to the core
Rust enum and propagate it through every surface that enumerates
`SearchType` — registry, HTTP DTO, C/Java/Python/TS bindings, and docs — so
the value round-trips end-to-end at the type level. Also extend
`SearchParams` with the six active + three reserved-inert hybrid knobs read
from `retriever_specific_config`, matching Python's
`get_search_type_retriever_instance.py:106-131` key names and defaults. This
task is pure plumbing: no retriever is registered, so `HYBRID_COMPLETION`
stays functionally unsupported (`SearchError::UnsupportedSearchType`) until
P1-09 lands the `HybridRetriever` port. Landing the wire/type surface first
lets every binding, doc, and cross-SDK harness stabilize on the final wire
name and knob schema before the retriever logic is written.

## Prerequisites

None — first task in the `hybrid-retriever` phase-1 series. Assumed state:
`main` at `82310dc`, workspace compiles clean, `scripts/check_all.sh` green.

  Python's `15`. P1-09 should fall back to `10` for consistency with every
  other Rust retriever — this is pre-existing, not introduced here.

  has `feedback_weight` but no `importance_weight` field yet — adding it is
  **out of scope for P1-01**; this task only threads the boolean
  `use_importance_weight` *knob*. The data-model change is an unnumbered
  prerequisite for P1-09 to have any real effect.
- **BM25 formula** (locked decision 1, out of scope, recorded for the
  implementing task): `/tmp/cognee-python/cognee/modules/retrieval/
  bm25_retriever.py` — `k1 = 1.5` (line 23), `b = 0.75` (line 24), stop
  words from `utils.stop_words.DEFAULT_STOP_WORDS` (line 6), length norm
  `k1 * (1 - b + b * len(tokens) / avg_len)` (line 95), score

  (lines 102-103). Distinct from the existing Jaccard-based
  `LexicalRetriever` (`crates/search/src/retrievers/lexical_retriever.rs`) —
  do not conflate; the hybrid chunk lane needs its own BM25 module.
  Per-query corpus rebuild (decision 5): must NOT reuse

  (`lexical_retriever.rs:29,48`).
