## Goal

Port Python's `cognee/modules/retrieval/hybrid/entities.py` and
`cognee/modules/retrieval/hybrid/facts.py` to
`crates/search/src/retrievers/hybrid/entities.rs` and
`crates/search/src/retrievers/hybrid/facts.rs`.
These modules turn already-fetched `Entity_name` and
`EdgeType_relationship_name` vector hits into the per-entity edge-bullet
blocks and the "Related facts" list the hybrid retriever renders into the LLM
prompt. Only `build_entities`'s graph-neighborhood fetch is I/O; everything
else is pure, so ranking/dedupe/gating can be pinned with exact-value tests
before the retriever wiring that calls these functions lands.

## Implementation steps

1. **Entity result type** in `entities.rs`: `id: String`, `name: String`,
   `description: Option<String>`, `entity_type: Option<String>`, `edges:
   Vec<EdgeBullet>` — mirrors `_entity_from_result` (`entities.py:86-98`).
   `id` via `result_id`; `name` via `first_display_value(name, text, id)`
   (falls back to the id, never empty); `description` via
   `display_value(description)`; `entity_type` via step 2.

2. **`_entity_type`** (`entities.py:122-127`): check `is_a` then `type`;
   return the first nonblank `display_value` that isn't the literal
   `"IndexSchema"`; else `None`. Shared by entity construction and bullet
   formatting.

3. **`build_entities`** (`entities.py:15-44`) as `pub async fn
   build_entities(graph: &dyn GraphDBTrait, entity_hits: &[SearchItem],
   max_edges_per_entity: usize, edge_ranks: &HashMap<String, usize>) ->
   Vec<EntityResult>`: return `[]` on empty hits; build one entity per hit
   and collect nonempty ids; if none are nonempty, return the entities
   unedited (no neighborhood call, mirrors lines 26-27). Call
   `graph.get_neighborhood(&ids, 1).await`; on `Err`, `tracing::warn!` and
   return entities with empty `edges` — **never propagate the error** (see
   `test_graph_neighborhood_error_keeps_chunks_entities_and_facts`,
   `hybrid_retriever_test.py:1346-1381`). Partition (step 4), then build
   bullets per entity (step 5).

4. **`_partition_neighborhood`** (`entities.py:47-72`): types
   `GraphNode = (String, NodeData)` / `EdgeData = (String, String, String,
   NodeData)` (`crates/graph/src/types.rs:14-25`) already line up 1:1 with
   Python's tuples. Build `nodes_by_id: HashMap<String, NodeData>`
   (id-with-`"id"`-key-inserted so a missing lookup still resolves to
   something); seed `connections: HashMap<String, Vec<(NodeLite, EdgeLite,
   NodeLite)>>` with an empty `Vec` per entity id (line 57). For each edge,
   build the `(source, {relationship_name, properties}, target)` triple and
   push it onto `connections[source_id]` if `source_id` is a key, and onto
   `connections[target_id]` if it's a key **and** `!= source_id` (self-loop
   dedupe, line 70). **An edge with neither endpoint in the seed ids
   (neighbor-to-neighbor) is silently dropped** — intentional, do not
   surface it elsewhere. Rust's typed `EdgeData`/`GraphNode` inputs mean
   malformed-shape handling (Python's `test_malformed_neighborhood_rows_...`,
   lines 959-982) mostly collapses to P1-06's `get_neighborhood` boundary;
   this function only needs to guard missing lookups.

5. **`_edge_bullets_from_connections`** (`entities.py:130-161`): return `[]`
   if `max_edges == 0`. Build a bullet per connection (step 6), skip empty
   text. Dedupe on two **independent** tracks: if `edge_dedupe_key` (step 8)
   is `Some`, dedupe on that triple in one `HashSet`; if `None`, dedupe on
   exact bullet text in a separate `HashSet` — a keyed bullet is never
   checked against the text set or vice versa (lines 137-138, 149-158). Sort
   by `edge_sort_key` (step 7) with a **stable** sort (`sort_by`/
   `sort_by_key`, matching Python's stable `list.sort`, so equal-key
   bullets keep connection order — matters for the `(2, 0)` bucket).
   Truncate to `max_edges`.

6. **`_edge_bullet`** (`entities.py:183-201`): labels via `_node_label`
   (step 9); `relationship` via `display_value(relationship_name)`; `text`
   prefers top-level `edge_text` (always absent in practice from step 4's
   triples — keep the check for fidelity) then nested
   `properties.edge_text` (step 10); if still empty and
   source/relationship/target labels are all present, synthesize
   `"{source} -- {relationship} -- {target}"`; if still empty, drop the
   bullet (`None`). `edge_type_id` **must** call
   `facts::connection_edge_type_id` (step 12) — not raw
   `relationship_name` (see Parity notes). Populate
   `source`/`target`/`source_id`/`target_id`/`relationship` from the same
   `display_value`d fields.

7. **`_edge_sort_key`** (`entities.py:164-171`) → `(u8, usize)`: `(0, 0)` if
   `is_type_edge` (step 11); else look up `edge_ranks[edge_type_id]` → `(1,
   rank)` if found, else `(2, 0)`.

8. **`_edge_dedupe_key`** (`entities.py:204-210`): `Some((source_id,
   relationship, target_id))` only when all three are nonblank; else
   `None`.

9. **`_node_label`** (`entities.py:231-233`): `first_display_value(name,
   id)`.

10. **`_nested_edge_text`** (`entities.py:224-228`):
    `display_value(properties.get("edge_text"))`, `None` if `properties`
    absent/not a map.

11. **`_is_type_edge`** (`entities.py:213-221`): normalize `relationship`
    (lowercase, `_`/`-` → space, trim) and compare to `"is a"`; else check
    whether the bullet text, lowercased and padded, contains `" is a "`.
    Rust type-edges carry relationship name `is_a` (underscore): ontology
    edges go through `generate_edge_name` (defined in
    `crates/utils/src/id_generation.rs:114`, delegating to
    `normalize_identifier` at `id_generation.rs:149-151`, spaces→underscores;
    called from `crates/cognify/src/graph_integration/expansion.rs:525`), and
    the structural Entity→EntityType edge from `get_graph_from_model` is
    emitted with the `"is_a"` relationship name (confirmed at
    `expansion.rs:919`, and `Entity.is_a` is set at `expansion.rs:471-477`); the underscore→space normalization here
    is exactly what matches both — don't special-case the underscore
    separately.

12. **`connection_edge_type_id`** (`facts.py:13-25`) in `facts.rs`: `pub fn
    connection_edge_type_id(edge: &EdgeLite) -> Option<String>` over the
    same `EdgeLite` entities.rs builds — keep the intermediate edge shape
    identical between the two modules so this is a direct pass-through.
    Mirror Python exactly: `nested_edge_text = properties.get("edge_text")`;
    `text = first_display_value(edge.edge_text, nested_edge_text)` — the
    top-level `edge_text` is checked **first**, same as step 6 (always
    absent in practice from step 4's triples, kept for fidelity); then
    `retrieval_text = EdgeType::retrieval_text(text.as_deref(),
    relationship_name)` (P1-05, `edge_type.rs:59-64`). Empty
    → `None`; else `Some(EdgeType::deterministic_id(&retrieval_text)
    .to_string())` (`crates/models/src/edge_type.rs:45-47`, matches
    Python's `EdgeType.id_for(retrieval_text)`).

13. **`edge_rank_by_id`** (`facts.py:28-34`): `pub fn edge_rank_by_id(hits:
    &[SearchItem]) -> HashMap<String, usize>` — iterate in order, insert
    `(result_id, rank)` only if nonblank and not already present
    (first-occurrence wins).

14. **`select_facts`** (`facts.py:37-54`): `pub fn select_facts(hits:
    &[SearchItem], exclude_ids: &HashSet<String>, facts_top_k: usize) ->
    Vec<FactResult>` (`FactResult { id, text }`). `used_ids` starts as a
    clone of `exclude_ids`. Stop once `facts.len() >= facts_top_k` (checked
    *before* each hit, so `facts_top_k == 0` → `[]` immediately regardless
    of hit count). Skip a hit if `result_id` is blank, or
    `first_display_value(text, relationship_name)` is blank, or the id is
    already used. Skip if word count `< MIN_FACT_WORD_COUNT` (const `3`,
    `facts.py:7`) using whitespace-run splitting (Python `str.split()`
    semantics, not `split(' ')`). Else mark the id used and push `{ id,
    text: fact_display_text(text) }`.

15. **`_fact_display_text`** (`facts.py:57-62`): if `text` doesn't start
    with the exact literal `"Document chunk mentions "` (const
    `CONTAINS_FACT_PREFIX`, line 10), return unchanged; else strip the
    prefix and upper-case **only the first remaining character**
    (`stripped[:1].upper() + stripped[1:]` — not a full-string uppercase).

16. **`format_facts`** (`facts.py:65-69`): `""` if no fact has nonempty
    text; else `"## Related facts\n"` + one `"- {text}"` line per fact,
    newline-joined.

17. **`format_entities`/`_format_entity`** (`entities.py:75-119`): `""` if
    no entity yields a nonempty block, else `"## Relevant entities\n"` +
    blocks joined by `"\n\n"`. A block is `""` (entity dropped entirely) if
    `display_value(name)` is blank; else `"### {name} ({type})"` or
    `"### {name}"`, then the description line if present, then one
    `"- {edge.text}"` per edge with nonblank text.

## Parity notes

- **`edge_type_id` recompute is edge-text-first — the subtle parity trap.**
  `index_graph_edges.py`'s `create_edge_type_datapoints`
  (`index_graph_edges.py:39-53`) counts `_get_edge_text(edge)` (lines
  32-36: nonblank `edge_text` else `relationship_name`) — **not** raw
  `relationship_name` — when building the `EdgeType` vector rows. A
  "contains" chunk→entity edge has `relationship_name == "contains"` but
  `edge_text == "Document chunk mentions ..."`; its point id is
  `EdgeType.id_for("Document chunk mentions ...")`. Using
  `relationship_name` directly would make such edges never rank
  (`(2, 0)` always) and let `select_facts`'s bullet-exclusion set miss a
  duplicate. Pinned by
  `test_connection_edge_type_id_prefers_top_level_edge_text` /
  `_reads_nested_properties_edge_text` / `_falls_back_to_relationship_name`
  (`hybrid_facts_test.py:23-36`).
- **`EdgeType::deterministic_id`** (`edge_type.rs:45-47`, via
  `cognee_utils::data_point_id_for`) already matches Python's
  `_normalize_identity_value` + `id_for` (`DataPoint.py:147-176`) — pinned
  by existing tests in `edge_type.rs`; this task adds a new caller, not new
  id-scheme risk.
- **`_edge_sort_key` is a strict 3-way partition**: `(0,0)` always before
  `(1,rank)` always before `(2,0)`. `test_is_a_edge_is_prioritized_before_edge_cap`
  (`hybrid_retriever_test.py:888-916`) shows an unranked `is_a` edge beats a
  ranked-looking `owns` edge for the single slot under `max_edges_per_entity=1`.
- **Dedupe is two independent tracks**: `test_same_edge_text_does_not_collapse_distinct_relationships`
  (`hybrid_retriever_test.py:862-884`) — two edges sharing `edge_text` but
  different `target_id`s both survive (different keys); a literal duplicate
  triple collapses to one. `test_duplicate_edges_are_removed_and_max_edges_caps_results`
  (lines 836-858) — edges with blank `relationship_name` fall to the
  text-only track and collapse there, then the edge cap truncates.
  `test_edge_between_two_retrieved_entities_appears_under_both`
  (lines 1236-1259) — one edge between two co-retrieved entities produces
  one bullet under **each** entity (partition dual-push, not a dedupe
  concern).
- **Fact gating lives in the caller** (`hybrid_retriever.py:200-211`):
  facts run only when `facts_top_k > 0` and `node_name` is unset; this
  task's `select_facts` just needs `facts_top_k == 0` → `[]` so that gate
  can be a thin wrapper.
- **Literal constants**: `MIN_FACT_WORD_COUNT = 3` (`facts.py:7`),
  `CONTAINS_FACT_PREFIX = "Document chunk mentions "` (line 10, exact
  string incl. trailing space).
- **Known limitation — document, do not fix here**: Rust's
  `expand_with_nodes_and_edges` port
  (`crates/cognify/src/graph_integration/expansion.rs:471`,
  `Entity::new(&node.name, None, &node.name, Some(dataset_id))`) never
  propagates the chunk's NodeSet names into `belongs_to_set` (zero
  `belongs_to_set` hits in that file); the field only carries the
  dataset-UUID default from the `DataPoint` base constructor
  (`crates/models/src/data_point.rs:135`, via `Entity::new` →
  `DataPoint::with_metadata`), and a dataset-UUID string never matches a
  `node_name` filter of NodeSet names. Python entities inherit
  `data_chunk.belongs_to_set` (`expand_with_nodes_and_edges.py:78`) so a
  `node_name`-scoped
  search can find `Entity_name` rows via `payload_matches_node_filter`
  (`hybrid/results.py:35-51`); on this workspace a scoped hybrid search's
  `Entity_name` query structurally returns **zero** entity hits — a
  strictly narrower miss than Python's
  `test_scoped_search_keeps_bullet_ranking_but_hides_facts`
  (`hybrid_retriever_test.py:1263-1293`), which keeps entities and hides
  only facts. Out of scope for this task; record it in a module-level
  comment at the top of `entities.rs`.
- **Structural, not bit-identical, parity** (locked decision 2): acceptance
  is same-algorithm + exact constants + overlapping top-k against
  `e2e-cross-sdk` (~50% tolerance), not byte-identical output — but this
  task's pure functions (dedupe/sort keys, word-count gate, prefix rewrite)
  are still asserted to exact values in unit tests, since they're
  deterministic given deterministic input.

## Risks & open items

- This task assumes P1-05/P1-06/P1-07 land first with the exact helpers
  described in Prerequisites. A differing name/signature/location from any
  of them needs a small reconciliation pass here, not a redesign — the
  algorithm doesn't depend on the dependency's exact shape.
- P1-06's ladybug direction-flip fix is a correctness dependency for
  `_edge_bullet`'s synthesized `"{source} -- {rel} -- {target}"` text: if
  direction is wrong, the fallback text reads backwards for entities that

  treating ladybug-backed integration runs of this task's bullets as
  trustworthy.
- The `belongs_to_set`-on-entities gap means `node_name`-scoped hybrid
  search loses entities entirely (not just facts) on this workspace until
  a later backfill task propagates the chunk's NodeSet names through
  `expand_with_nodes_and_edges`. Tracked as a known follow-up, not a
  blocker here.
