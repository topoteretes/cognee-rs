## Goal

Wire the currently-inert `use_truth_weight` knob into `HybridRetriever`'s
chunk-ranking lane: when the flag is on and exactly one dataset is in scope,
load that dataset's truth centroids, project the query into truth-subspace
coordinates, batch-fetch the candidate chunks' truth state from the graph,
and apply `truth_factor` as a score multiplier in ranking — with a single
fail-open path back to baseline on *any* error, mirroring Python's one
`try/except` around the whole computation. This is the piece that connects
the pure math (P2-01), centroid slots (P2-02), and vector persistence (P2-03)
to a real, still default-off, retrieval-time effect.

Signature takes the *resolved* `use_truth_weight` bool explicitly, not `self.use_truth_weight`, so a per-request `SearchParams` override (P1-01) is honored — Python's field is constructor-only with no per-request override; this parameter is a Rust-only addition required by locked decision 8, not a divergence to hide:
   ```rust
   async fn build_truth_context(
       &self,
       use_truth_weight: bool,
       query_vector: &[f32],
       dataset_id: Option<Uuid>,
   ) -> (Option<Vec<f64>>, Option<HashMap<String, NodeTruthState>>, Option<i64>) {
       if !use_truth_weight {
           return (None, None, None);
       }
       let Some(dataset_id) = dataset_id else {
           return (None, None, None);
       };
       match self.try_build_truth_context(query_vector, dataset_id).await {
           Ok(Some((q_coords, truth_state_by_id, current_truth_epoch))) => {
               (Some(q_coords), Some(truth_state_by_id), Some(current_truth_epoch))
           }
           Ok(None) => (None, None, None),
           Err(error) => {
               tracing::debug!(%error, "truth-subspace lookup failed; using baseline ranking");
               (None, None, None)
           }
       }
   }
   ```

6. **`try_build_truth_context`** — the fallible inner body, returning
   `Result<Option<(Vec<f64>, HashMap<String, NodeTruthState>, i64)>, SearchError>`
   (the `Option` layer distinguishes "empty centroids → no truth context" from
   a hard error; both collapse to `(None, None, None)` in step 5, but keeping
   them distinct here avoids threading a fake error through `?` for a
   non-error case). Every `.await?` on `vector_db`/`graph_db` propagates via
   the existing `From<VectorDBError>`/`From<GraphDBError>` impls on
   `SearchError` (`crates/search/src/types/errors.rs:36-46`):
   ```rust
   async fn try_build_truth_context(
       &self,
       query_vector: &[f32],
       dataset_id: Uuid,
   ) -> Result<Option<(Vec<f64>, HashMap<String, NodeTruthState>, i64)>, SearchError> {
       let centroids = load_centroids(self.vector_db.as_ref(), &dataset_id.to_string(), DEFAULT_K).await?;
       if centroids.is_empty() {
           return Ok(None);
       }

       let centroid_vectors: Vec<Vec<f64>> = centroids.iter().map(|c| c.centroid.clone()).collect();
       let query_vector_f64: Vec<f64> = query_vector.iter().map(|v| *v as f64).collect();
       let q_coords = pad_coords(&query_coords(&query_vector_f64, &centroid_vectors), DEFAULT_K);
       let current_truth_epoch = centroids
           .iter()
           .map(|c| c.truth_epoch)
           .max()
           .expect("centroids is non-empty, checked above");

       let candidate_ids = self.candidate_chunk_ids(query_vector).await?;
       if candidate_ids.is_empty() {
           return Ok(Some((q_coords, HashMap::new(), current_truth_epoch)));
       }

       let truth_state_by_id = self.graph_db.get_node_truth_state(&candidate_ids).await?;
       Ok(Some((q_coords, truth_state_by_id, current_truth_epoch)))
   }
   ```
   Behaviorally identical to `hybrid_retriever.py:120-140` at every branch (see Parity notes for the line-by-line mapping).

## Parity notes

- **Exact source lines**: `_build_truth_context` = `hybrid_retriever.py:110-143`; `_candidate_chunk_ids` = `hybrid_retriever.py:145-165`; ranking multiplier = `hybrid/ranking.py:39-44`. Verified against `/tmp/cognee-python`.
- **Single fail-open boundary**: Python wraps the entire `_build_truth_context` body in one `try/except Exception`, logging at `debug` and returning `None, None, None` (`:120,141-143`). The Rust port keeps this as one fallible chain (`try_build_truth_context`) — a partial failure (centroids load OK, graph batch call errors) must still discard the already-computed `q_coords` and fail all the way open, not swallow errors per-step.
- **Candidate-empty ≠ fail-open**: `hybrid_retriever.py:134-135` returns `(q_coords, {}, current_truth_epoch)` — all populated, just an empty state map — when the candidate-chunk search yields nothing. Only genuine errors or zero centroids fail fully open.
- **`q_coords` truthiness in the ranking gate** (`ranking.py:40`): Python's `and q_coords` is list-truthiness, false for both `None` and `[]`. Since `pad_coords` always returns a `DEFAULT_K`-length vector whenever centroids exist, an empty-but-`Some` `q_coords` is unreachable in practice, but the Rust gate must still check emptiness explicitly (`q_coords.map(|c| !c.is_empty()).unwrap_or(false)`), not just `is_some()`, to stay a structural match rather than accidentally diverging if `DEFAULT_K` ever became configurable to `0`.
- **Epoch equality, not inequality** (`ranking.py:42`): a chunk whose stored `truth_epoch` is older than the dataset's current max epoch gets no multiplier at all — stale alignments are "no signal," not a discounted signal, and this is scoped per-chunk, not per-request.
- **Missing-from-map ⇒ no multiplier**: identical treatment to stale-epoch — both silently skip the multiplier, matching Python's `(truth_state_by_id or {}).get(chunk_id, {})` defaulting to `{}` whose `.get("truth_epoch")` is `None`.
- **`chunk_id` resolution** (`ranking.py:39`): `pair["chunk_id"] or result_id(chunk) or ""` — prefer the pair's carried id, fall back to re-deriving from the chunk payload, fall back to `""` (never matches any real map key). Reuse whatever `result_id`-equivalent helper P1-05/P1-06 already exposes in `hybrid::results`; do not reimplement it.
- **`f32` → `f64` embedding upcast**: Rust's embedding pipeline yields `Vec<f32>`; `cognee-truth-subspace` operates on `f64` slices. Upcast once at the `try_build_truth_context` boundary — lossless, intentional, not a cross-SDK divergence.
- **Dataset scope singularity** (Rust-only design decision, no direct Python line — Python's `current_dataset_id` contextvar is implicitly single-valued): the truth lane activates only when `SearchRequest.dataset_ids` resolves to exactly one id. Zero or 2+ ids both fail open via `SearchParams.dataset_id == None`, since truth centroids are built per-dataset (P2-02/P2-03) and there is no well-defined single truth-subspace across multiple datasets at once.
- **Structural, not bit-identical, parity** (locked decision 2): unlike P2-01's exact-`f64` acceptance bar, this task's acceptance bar is overlapping top-k ranking at the same ~50% e2e-cross-sdk tolerance already accepted for the surrounding RRF/importance ranking.

- **`build_truth_subspace` remains fully inert after this task.** Without a landed build/execution task, no dataset ever has real centroids, so `load_centroids` always returns empty in production and the truth lane fails open on every real request regardless of `use_truth_weight`. This task is provably correct only via the mocked tests above until that build task lands — call this out in any PR description.

- **Per-request `use_truth_weight` override is a Rust-only addition** (Python's is constructor-only), required by locked decision 8. Worth a one-line callout in user-facing docs so it isn't mistaken for an oversight.
