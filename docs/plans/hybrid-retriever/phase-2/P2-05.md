# P2-05 — Session-learnings distillation gate

**Status:** completed

## Goal

Port Python's session-distillation pipeline
(`cognee/modules/session_distillation/distill.py`, 405 lines: curate → propose
→ evaluate → publish) into `cognee-cognify`, and wire it into Rust `improve()`
as a new Stage 2c that runs after trace-step persistence and before default
enrichment. This is the gate that decides which pieces of a finished session's
Q&A become durable, entity-anchored lesson documents in the permanent graph —
tagged with both the generic `session_learnings` NodeSet and the per-session
`session_learnings:{session_id}` NodeSet, so later Phase-2 work
(`build_truth_subspace`, deferred) has anchors to build centroids from.
No sessions supplied ⇒ the stage is a no-op, same as every other session-gated
stage in `improve()`.

## Implementation steps

1. Re-read `distill.py` (405 lines) and `models.py` (98 lines) once more
   before coding; vendor `session_distillation_curator_system.txt` and
   `session_distillation_writer_system.txt` verbatim into
   `crates/cognify/src/memify/prompts/`, loaded via `include_str!` (same
   pattern as `DEFAULT_GRAPH_PROMPT` in
   `crates/cognify/src/fact_extraction/extractor.rs:27`).

2. **Tunables** (`models.py:15-35`) as `pub const` in `distill_sessions.rs`:
   `CURATOR_BLOCKS_PER_BATCH: usize = 6`, `MAX_QA_QUESTION_CHARS: usize =
   1_200`, `MAX_QA_ANSWER_CHARS: usize = 1_200`, `CURATOR_CONCURRENCY: usize =
   5`, `WRITER_CONCURRENCY: usize = 5`, `NOVELTY_LESSONS_PER_LESSON: usize =
   5`, `GLOSSARY_ENTITIES_PER_LESSON: usize = 20`. **Do not port**
   `MIN_GATE_CONFIDENCE`/`MAX_CANDIDATE_CHARS` (`models.py:19,27`) — both only
   filter `SessionContextEntry` rows, a subsystem Rust doesn't have (see
   Prerequisites); doc-comment the omission on the module. Also skip
   `BATCH_CHAR_BUDGET` (`models.py:23`) — it is comment-only documentation in
   Python, never imported by `distill.py`.

3. **Schemas** (`models.py:41-82`), deriving `Debug, Clone, Serialize,
   Deserialize, schemars::JsonSchema` (same derive set as `BatchedGraphs` in
   `crates/cognify/src/fact_extraction/extractor.rs:42-47`):
   `ProposedLesson { working_statement: String, #[serde(default)]
   member_entry_ids: Vec<String> }`; `CuratorBatchOutput { #[serde(default)]
   lessons: Vec<ProposedLesson> }`; `WrittenLesson { accept: bool, reason:
   Option<String>, #[serde(default)] statement: String, #[serde(default)]
   entities: Vec<String>, #[serde(default)] why_learned: String }` (Python's
   `reason` is a 3-value `Literal`; use whatever enum-schema precedent
   `fact_extraction`/`temporal_extraction` already established for
   constrained-string fields, don't invent a new one). `DistillationResult {
   session_id: String, dataset_id: Option<Uuid>, status: DistillationStatus,
   documents: Vec<String> }`, with `DistillationStatus` = `Completed |
   NoQaEntries | NoProposedLessons | NoAcceptedLessons` — `NoQaEntries` is a
   **rename** of Python's `no_gated_entries` (`models.py:94`) because the
   Rust gate is "no non-empty Q&A", not "no gated context entries".

4. **`load_distillable_session_inputs`** (`distill.py:120-145`), Q&A only:
   `session_store.get_all_qa_entries(session_id, Some(&owner_id.to_string()))`
   (same call `persist_sessions_in_knowledge_graph` makes at
   `crates/cognify/src/memify/persist_sessions.rs:119-121`). No
   `get_session_context_entries` equivalent exists on `SessionStore`
   (`crates/session/src/session_store.rs:31-152`) — don't add one here. Gate:
   if every `question`/`answer` pair is empty after whitespace-collapse,
   return `NoQaEntries` immediately.

5. **`build_curator_batches`** (`distill.py:148-173`), QA-only: per
   `SessionQAEntry`, whitespace-collapse + truncate `question`/`answer` to
   `MAX_QA_QUESTION_CHARS`/`MAX_QA_ANSWER_CHARS`, format
   `"User: {question}\nAssistant: {answer}"`, skip if both empty, sort by
   `created_at: DateTime<Utc>` (a real timestamp — strictly better-ordered
   than Python's string-timestamp sort on `row.get("time")`), chunk into
   groups of `CURATOR_BLOCKS_PER_BATCH` joined by `"\n\n"`. No candidate
   blocks (`distill.py:162-165`) — no `SessionContextEntry` corpus to draw
   them from.

6. **`curate_batch`** (`distill.py:176-191`): one
   `LlmExt::create_structured_output::<CuratorBatchOutput>(batch_text,
   CURATOR_PROMPT, None)` per batch (`crates/llm/src/llm_trait.rs:165-186`;
   `None` options — Python passes no generation kwargs here either). `Err` ⇒
   `warn!`, return `vec![]` (fail-open per batch).

7. **`propose_lessons`** (`distill.py:194-207`): bounded fan-out over
   batches, `futures::stream::iter(...).map(|b| async move {
   curate_batch(b).await }).buffer_unordered(CURATOR_CONCURRENCY)`, then plain
   `.collect::<Vec<Vec<ProposedLesson>>>().await` and flatten — **not**
   `try_collect` (each future returns `Vec<_>` directly, never `Result`, so
   nothing should abort the stream on one bad batch). This is the Rust
   equivalent of Python's `gather_with_concurrency_limit`
   (`distill.py:204`); modeled on
   `crates/cognify/src/summarization/extractor.rs:190-206`'s
   `buffer_unordered` fan-out (that one uses `try_collect` because its
   per-item future *should* abort on error — ours must not).

8. **`search_payload_texts`** (`distill.py:210-247`) — the step with the
   largest Rust/Python API divergence (see Parity notes). Python's
   `vector_engine.search(collection, query_text=..., node_name=...)` takes a
   text query and NodeSet filter directly; Rust's
   `VectorDB::search_similar(data_type, field_name, query_vector: &[f32],
   top_k)` (`crates/vector/src/vector_db_trait.rs:67-73`) takes only a
   pre-embedded vector, no filter. Implement as: (a) embed the query text via
   `embedding_engine.embed(&[text]).await`; (b) call `search_similar` with an
   oversampled `top_k` when a NodeSet filter applies; (c) for the novelty
   search only (`("DocumentChunk", "text")`) filter results by
   `SearchResult.metadata["belongs_to_set"]`
   (`crates/models/src/data_point.rs:73`, dumped into vector metadata at
   indexing time via `vector_metadata()` — see
   `crates/cognify/src/tasks.rs:2739-2741`). **Element shape**: entries are
   NodeSet JSON objects `{"id", "name", "type": "NodeSet"}` built by
   `classify_documents` (`crates/models/src/document.rs:150-179`), **not**
   bare strings — a result matches when any element's `"name"` equals
   `"session_learnings"`;
   the glossary search (`("Entity", "name")`) needs no filter (Python passes
   none for it either, `distill.py:310-315`); (d) read `metadata["text"]`
   else `metadata["name"]`, dedupe case-insensitively
   (`.to_lowercase()`, same accepted divergence as P2-02's `learning_id`),
   preserve first-seen order, truncate to `limit`; (e) fail-open on **any**
   error including `VectorDBError::CollectionNotFound` (a fresh dataset with
   no collection yet is the common case — verified
   `crates/vector/src/brute_force_vector_db.rs` `search_similar` (the
   `.ok_or_else(|| VectorDBError::CollectionNotFound(...))` at ~line 199,
   inside the fn opening at line 184) errors rather than returning empty on a
   missing collection).

9. **`build_writer_input`** (`distill.py:250-267`): `"PROPOSED
   LESSON:\n{working_statement}"` then conditionally-appended (only if
   non-empty) `"MEMBER ENTRIES:\n..."` (will usually be empty — see step 4),
   `"SIMILAR EXISTING LESSONS:\n..."`, `"ENTITY GLOSSARY:\n..."`, joined by
   `"\n\n"`.

10. **`write_or_reject`** (`distill.py:270-291`): one
    `create_structured_output::<WrittenLesson>(writer_input, WRITER_PROMPT,
    None)` per proposed lesson; `Err` ⇒ `warn!`, return `None`.

11. **`evaluate_proposed_lesson`** (`distill.py:294-317`): `members` is
    always `vec![]` in this port (step 4's scope cut — document this rather
    than building dead lookup code); run the two `search_payload_texts` calls
    concurrently via `tokio::join!` (Python's `asyncio.gather`,
    `distill.py:302-316`); call `write_or_reject`.

12. **`accept_proposed_lessons`** (`distill.py:320-344`): bounded fan-out
    (`buffer_unordered(WRITER_CONCURRENCY)`, same collect-not-try_collect
    shape as step 7) over proposed lessons, filter to `lesson.accept &&
    !lesson.statement.trim().is_empty()`. Python's `async with
    set_database_global_context_variables(...)` (`distill.py:326`) has no
    Rust equivalent needed — `vector_db`/`embedding_engine` already arrive as
    explicit `Arc` parameters like every other `improve.rs` stage.

13. **`render_lesson_document`** (`distill.py:347-361`), pure string
    function: `statement = lesson.statement.trim()`; `why =
    lesson.why_learned.trim().trim_end_matches('.')`; body = `"{statement}
    ({why}.)"` if `why` non-empty else `statement` alone; return `"# Session
    learning — {distilled_on} (session {session_id})\n\n{body}\n"` where
    `distilled_on = chrono::Utc::now().format("%Y-%m-%d")` (matches Python's
    `datetime.utcnow().strftime("%Y-%m-%d")`, `distill.py:368`). This part is
    deterministic string formatting — expect byte-identical output to Python
    given the same inputs.

14. **`publish_distilled_lessons`** (`distill.py:364-381`): render one
    document per accepted lesson, then reuse the add→cognify shape already
    established by `persist_sessions_in_knowledge_graph`
    (`crates/cognify/src/memify/persist_sessions.rs:97-150`): call
    `add_pipeline.add_with_params(documents as DataInput::Text, dataset_name,
    owner_id, tenant_id, &AddParams { node_set: Some(vec![
    "session_learnings".to_string(), format!("session_learnings:{session_id}")
    ]), ..Default::default() })` — **both** tags on **every** document
    (Python: `node_set = [*DISTILLATE_NODE_SET,
    truth_session_node_set(scope.session_id)]`, `distill.py:378`); resolve
    the dataset UUID via `get_dataset_by_name` (same call `improve.rs`'s
    Stage 2b already makes at lines 421-431) and run
    `cognee_cognify::tasks::cognify(...)` on the returned rows, matching the
    call already inline in `improve.rs` Stage 2b (lines 433-449).

15. **`distill_session`** (`distill.py:384-405`): load Q&A (step 4) → early
    `NoQaEntries` if empty → `propose_lessons` → early `NoProposedLessons` if
    empty → `accept_proposed_lessons` → early `NoAcceptedLessons` if empty →
    `publish_distilled_lessons` → `Completed` with the rendered documents.

16. **`distill_sessions_in_knowledge_graph`**, a thin multi-session loop
    matching `_distill_sessions` (`improve.py:390-429`): call
    `distill_session` per id, catching errors per-session (`warn!`,
    non-fatal, matches `improve.py:423-428`), summing `documents.len()` into
    `DistillSessionsResult { sessions_distilled: usize, lessons_published:
    usize }`.

17. **Wire Stage 2c into `improve.rs`**: insert immediately after Stage 2b's
    closing brace (line 497; the `"persist_trace_steps"` push is at line 496)
    and before the Stage 3 comment
    (line 499), following the same `match (session_store.as_ref(),
    add_pipeline, db.clone()) { (Some(..), Some(..), Some(..)) => {...}, _ =>
    warn!(...) }` shape every other stage uses. Push `"distill_sessions"`
    onto `stages_run` **only if** `sessions_distilled > 0` (Python:
    `improve.py:200-201` — conditional on output, unlike Stage 2b's
    unconditional push). **Do not** port stage 2b2
    (`_extract_agent_context`, `improve.py:349-387`) — explicit scope cut,
    see Risks.

18. Update `ImproveResult`'s two new fields, the module doc comment, and
    `docs/operations.md`'s `### improve` section (one sentence).

19. Run: `cargo fmt`, `cargo check --all-targets`, `cargo test -p
    cognee-cognify -p cognee`, then `scripts/check_all.sh`.

## Parity notes

- **Node-set tags** (`distill.py:59,378`; `truth_subspace/constants.py:2,6-7`):
  every published lesson carries **both** `"session_learnings"` and
  `"session_learnings:{session_id}"` — the exact anchor set
  `build_truth_subspace` (deferred) will later scope its search to. Do not
  drop either tag.
- **Scope cut — no `SessionContextEntry` corpus**: Python's top-level gate is
  "no gated entries at all" (`distill.py:393-394`, `no_gated_entries`); Rust's
  is "no non-empty Q&A" (`NoQaEntries`). This is a locked, explicit reduction
  (see Prerequisites/Risks), not an oversight.
- **Scope cut — stage 2b2 (`_extract_agent_context`) skipped**
  (`improve.py:184-188,349-387`): it only feeds `SessionContextEntry` rows,
  which distillation never reads in this port, so it has nothing to feed.
- **Prompts are byte-identical to Python** (vendored verbatim); any future
  re-sync must diff against these two files.
- **LLM call shape**: no `GenerationOptions` overrides for curator or writer
  calls (Python passes no kwargs beyond `text_input`/`system_prompt`/
  `response_model`, `distill.py:183-187,283-288`).
- **Concurrency = 5/5** (`models.py:30-31`) via `buffer_unordered(n)`; unlike
  `summarize_chunks`'s index-preserving fan-out
  (`crates/cognify/src/summarization/extractor.rs:190-208`), output order
  does not need restoring here — both fan-outs only aggregate into a flat,
  order-insensitive collection.
- **Fail-open at three granularities** — one curator batch
  (`distill.py:189-191`), one writer call (`distill.py:289-291`), one session
  in the multi-session loop (`improve.py:423-428`) — never the rest of
  `improve()`. Keep all three levels distinct; don't collapse into one
  top-level try/catch.
- **`search_payload_texts` divergence**: Python's engine takes `query_text` +
  `node_name` directly; Rust's `search_similar` takes only a pre-embedded
  vector with no filter, so the port embeds first and filters
  `belongs_to_set` client-side post-search with oversampling. Structural, not
  semantic, divergence — acceptable under the ~50%-tolerance bar.
- **Casefold divergence**: `.to_lowercase()` vs Python `.casefold()` in the
  dedup step — same accepted gap already documented in P2-02's `learning_id`.
- **Acceptance bar is structural, not bit-identical**: same algorithm, same
  constants, overlapping accepted-lesson sets under the e2e-cross-sdk
  harness's existing ~50% tolerance — not exact LLM-output equality.

## Risks & open items

- **Gated-guidance subsystem is out of scope; follow-up needed.** When (if)
  `SessionContextEntry`/`session_context_builder` is ported to Rust,
  `load_distillable_session_inputs` must be revisited to read and gate on
  it, and `DistillationStatus::NoQaEntries` may need to split back into two
  variants (no-QA vs no-gated-entries) to preserve Python's status
  granularity.
- **Client-side NodeSet filtering in `search_payload_texts` is an oversampling
  heuristic**, not an exact translation of Python's server-side `node_name`
  filter — a true novelty match could be missed if more than `top_k *
  oversample_factor` non-matching candidates outrank it. Acceptable under the
  structural bar. **Update (finding F9):** the trait now exposes
  `VectorDB::search_similar_filtered(.., node_name, operator)`, a server-side
  filter-then-limit that is **exact** on the in-memory adapters
  (`BruteForceVectorDB`, `MockVectorDB`) and pgvector, and a bounded
  client-side fallback (widen-to-collection under
  `NODE_FILTER_RECALL_FETCH_CAP`) on the LanceDB / default path whose
  `metadata` is an opaque JSON string. The hybrid chunk lane
  (`retrievers/hybrid/chunks.rs::search_collection`) already routes through it;
  `search_payload_texts` could adopt it too for exact novelty-search recall on
  the filterable backends — a small follow-up, no longer a trait change.
- **`WrittenLesson.reason` schema shape** (enum vs `Option<String>`) is an
  implementation-time decision — follow whatever precedent
  `fact_extraction`/`temporal_extraction` already established for
  constrained-string fields rather than introducing a new pattern.
- **No cross-SDK e2e test added here.** A future task should add an
  `e2e-cross-sdk` case comparing Python- and Rust-distilled lesson counts
  (structural, ~50% tolerance) once both sides are stable.
- **`cognee-truth-subspace` crate identity unconfirmed** at the time this
  lands — reconcile this task's local `session_learnings:{session_id}`
  helper with `cognee_truth_subspace::truth_session_node_set` if that crate
  exists by then, to avoid two divergent copies of the same format string.
